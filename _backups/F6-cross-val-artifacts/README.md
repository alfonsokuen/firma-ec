# F6 cross-validation artifacts (PAdES B-T)

Sample PDFs to validate firma.ec's PAdES output across ecosystems before
declaring F6 LIVE. Generated 2026-05-10 via `scripts/gen-f6-samples.mjs`
hitting the REAL FreeTSA endpoint (https://freetsa.org/tsr).

## Files

| File | Size | CMS bytes | TSToken |
|---|---|---|---|
| `sample-b-b-no-tsa.pdf` | 18 744 B | 1 459 | absent |
| `sample-b-t-freetsa.pdf` | 18 744 B | 6 117 | present (RFC 3161, FreeTSA) |

Same signer cert (`rsa2048-valid.p12` test fixture, CN "Test Signer RSA-2048")
on both — only difference is the embedded `id-aa-signatureTimeStampToken`
unsigned attribute on the B-T sample.

> **Note**: this signer cert is a self-signed test fixture, not chained to
> any trust anchor. Cross-validation tools will report "signature mathematically
> valid but signer not trusted" — that is expected and not a defect. The point
> of the artifacts is to validate **PAdES structure** + **TSToken embedding**,
> not trust chain.

## How to verify in Adobe Reader DC (manual, post-deploy)

1. Open `sample-b-b-no-tsa.pdf` in Adobe Acrobat Reader DC.
2. Click the Signature Panel icon (left sidebar pen-on-paper icon) or
   `Ctrl+Shift+E`.
3. Expected:
   - Status: "At least one signature has problems" (because the test cert
     isn't trusted) **but** "Signature is mathematically valid" when expanded.
   - Timestamp: section absent / "Signature is not timestamped".
4. Open `sample-b-t-freetsa.pdf`.
5. Expected:
   - Same mathematically-valid status PLUS
   - "Signature includes an embedded timestamp" with a date matching the
     FreeTSA response time (~2026-05-10 around 04:13 UTC).
6. To trust FreeTSA's TSA root in Adobe (one-time, optional):
   - Edit → Preferences → Signatures → Identities & Trusted Certificates → More.
   - Trusted Certificates → Import → load
     `packages/tsa-trust/src/roots/freetsa.pem`.
   - Set "Use this certificate as trusted root" + "Signed documents or data".
   - Re-open the B-T PDF; the timestamp section should now show "Trusted".

## How to verify in FirmaEC desktop (Java, ECI reference impl)

1. Open the FirmaEC app (https://www.firmadigital.gob.ec/firmaec).
2. Validar firma → select `sample-b-t-freetsa.pdf`.
3. Expected: the SignatureTimeStamp attribute is recognised and the TSA
   identity is shown ("FreeTSA" / "FreeTSA CA Root"). Signer trust will
   fail (test cert) — focus on the TSToken section.

## How to verify in firmar.ec self-test (round-trip)

1. Visit https://app.firmar.ec/verificar (or local `pnpm -F @firma-ec/pwa preview`).
2. Drop `sample-b-t-freetsa.pdf`.
3. Expected: gold "Sellada @ <ISO date>" TimestampBadge with role="status".
4. Drop `sample-b-b-no-tsa.pdf`.
5. Expected: signature panel renders, NO gold timestamp badge (B-B path).
